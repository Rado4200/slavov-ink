# Internationalization

Locales: **bg**, **en**, **es**, **de**. Default and fallback: **en**
(`defaultLocale` in `src/i18n/config.ts`, one line to change).

## Decision: custom, no i18n library

Evaluated next-intl 4.14.9 against a minimal custom layer for Next 16.4 (Cache
Components on, `proxy.ts`, static rendering, typed messages), using the current
Next docs in `node_modules/next/dist/docs` and next-intl's docs and issue tracker
(October 2026).

1. Next 16.4 already provides what we need: a `[locale]` root segment,
   `next/root-params` (read the locale anywhere on the server; it becomes part
   of the `"use cache"` key automatically), `generateStaticParams`, and `proxy.ts`.
2. next-intl's Cache Components support is still settling: there is an open report
   (Sep 2026) of the layout staying on the old locale after a client-side locale
   switch, with a fix pending in Next.js.
3. Our needs are small (about 40 strings, no plurals or ICU yet), all rendered
   on the server, so messages add **zero** client JS.
4. Typed JSON plus `satisfies` gives compile errors on missing keys and full
   autocomplete, with no code generation; `pnpm i18n:check` covers the rest.
5. No new dependency. The message layout (`<locale>/<namespace>.json`) is
   next-intl-compatible, so migrating later is cheap if we need ICU plurals or
   rich text.

## How it works

| Piece                             | Role                                                                                                                                                                            |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/i18n/config.ts`              | Locales, default locale, cookie name, language endonyms, OG locales.                                                                                                            |
| `src/proxy.ts`                    | Locale-less URLs only (`/`, `/about`): redirect by saved cookie, then `Accept-Language`, then default. Locale pages never hit it, so they stay fully static.                    |
| `src/app/[locale]/layout.tsx`     | Root layout: `<html lang>`, `generateStaticParams` (all 4 locales prerendered).                                                                                                 |
| `src/i18n/messages.ts`            | `getLocale()` / `getMessages()` via `next/root-params` (server only), `format()` for `{placeholders}`.                                                                          |
| `src/i18n/metadata.ts`            | Per-page title/description, canonical, `hreflang` alternates (incl. `x-default` → en), `og:locale`.                                                                             |
| `src/messages/<locale>/*.json`    | Namespaces: common, nav, footer, home, about, portfolio, notFound, a11y.                                                                                                        |
| `src/app/sitemap.ts`, `robots.ts` | Sitemap with per-language alternates; dev routes disallowed.                                                                                                                    |
| `LanguageSwitcher`                | BG · EN · ES · DE in the header and mobile menu. Plain links (full page load, so `<html lang>` and the root layout always re-render), keeps the path, sets the `locale` cookie. |

Unknown paths under a locale (`/de/xyz`) render the localized 404. URLs outside
every route fall back to `src/app/global-not-found.tsx` (English, with links to
all four languages).

## Rules

- All user-visible text lives in `src/messages/`; components receive strings.
  Language-neutral data (brand name, URLs, email) stays in `src/content/site.ts`.
- English is the schema. Add a key to `en/<ns>.json` first, then to every
  other locale; `pnpm typecheck` fails until all locales have it.
- `pnpm i18n:check` fails on missing/extra keys, mismatched `{placeholders}`,
  empty strings, strings identical to English (unless listed in
  `scripts/i18n-allowlist.json`), and a proxy matcher out of sync with the
  config. `TODO:` placeholders are reported but do not fail.
- Adding a locale: add it to `locales` in `config.ts` and `localeMeta`, add it to
  the matcher in `src/proxy.ts`, create `src/messages/<locale>/` with an
  `index.ts` like the others, and register it in `src/i18n/messages.ts`.
